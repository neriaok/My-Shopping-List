# רשימת קניות - גרסת TypeScript

גרסה מפורקת ומטופסת (typed) של אפליקציית רשימת הקניות, מובנית כפרויקט React + TypeScript + Vite סטנדרטי. נבנתה מתוך גרסת ה-JSX החיה (single-file) כדי להדגים ארגון קוד ברמת פרודקשן/פורטפוליו.

## הרצה מקומית

```bash
npm install
npm run dev      # שרת פיתוח
npm run test     # טסטים (vitest)
npm run build    # בנייה לפרודקשן
```

## מבנה התיקיות

```
src/
  types/          # טיפוסי TypeScript משותפים (Aisle, ShoppingItem, KeywordsMap...)
  utils/
    categorize.ts       # פונקציה טהורה לסיווג אוטומטי + נירמול עברית
    categorize.test.ts  # יחידות בדיקה
  hooks/
    useShoppingList.ts  # כל ה-state והלוגיקה העסקית, כולל persistence
  components/
    ShoppingNote.tsx     # שלב 1 - כתיבה חופשית
    CategoryNote.tsx     # פתק בודד לקטגוריה בשלב הקנייה
    ManagePanel.tsx       # ניהול קטגוריות ומילות מפתח
    ProgressBar.tsx
  App.tsx           # מרכיב הכל יחד לפי ה-mode הנוכחי
```

## החלטות ארכיטקטורה מרכזיות (ולמה)

**1. כל הלוגיקה ב-custom hook אחד (`useShoppingList`)**
קומפוננטות ה-UI "טיפשות" בכוונה - הן מקבלות props ו-callbacks, ולא יודעות איך המידע נשמר או מסווג. זה מפריד "מה מוצג" מ-"איך המערכת עובדת", והופך את הלוגיקה לניתנת לבדיקה בלי לרנדר שום דבר.

**2. `categorize` היא פונקציה טהורה, נפרדת מה-state**
אין תלות ב-React בכלל - קלט קבוע תמיד מייצר פלט קבוע. זה מה שמאפשר לה קובץ טסטים משל עצמה (`categorize.test.ts`) בלי מוקים או רינדור.

**3. מזהים עם `crypto.randomUUID()` במקום מונה גלובלי**
בגרסת ה-JSX המקורית היה `let nextId = 1` ברמת המודול - עובד, אבל לא אידיומטי (בעייתי מול Strict Mode / HMR / SSR). כאן המזהה נוצר בתוך ה-hook, בלי state חיצוני לקומפוננטה.

**4. `useMemo` על ערכים נגזרים**
`groups`, `checkedCount`, `unmatchedItems` מחושבים מ-`items`/`aisles` הקיימים, לא נשמרים כ-state כפול. ה-`useMemo` פה הוא בעיקר תיעוד כוונה (declare "זה נגזר, לא state") - ברשימות בסדר גודל כזה לא קריטי לביצועים.

**5. Persistence עם `localStorage` בתוך ה-hook**
טעינה חד-פעמית ב-`useEffect` עם מערך תלויות ריק, שמירה בכל שינוי רלוונטי עם דגל `loaded` שמונע דריסת הנתונים השמורים לפני שהטעינה הסתיימה.

## מה עוד הייתי מוסיף עם יותר זמן

- **מחיקה/עריכת שם לקטגוריה קיימת** (יש רק יצירה כרגע)
- **Drag & drop** לסידור מחדש של סדר הקטגוריות
- **Context** או ספריית state (Zustand) אם האפליקציה תגדל מעבר לזה - כרגע hook יחיד עדיין קריא, אבל זה הגבול
- **Error boundary** סביב `App`
- **טסטים לקומפוננטות** (לא רק ל-utils) עם React Testing Library

## התאמה למובייל

הגרסה הזו כוללת כמה תיקונים ספציפיים שהגרסה החיה (ה-JSX המקורי) לא כללה:

- **אזורי מגע**: הצ'קבוקסים והכפתורים (`CategoryNote`, `ManagePanel`) עטופים בכפתור עם שטח לחיצה של כ-40x40px, גם כשהאלמנט החזותי בפנים (למשל התיבה על הפתק) נשאר קטן ודק - כדי לשמור על האסתטיקה בלי להקריב נוחות מגע. זה קרוב לסטנדרט המומלץ (44x44) בלי לפגוע בעיצוב.
- **כותרות רספונסיביות**: `fontSize: clamp(...)` על הכותרות הראשיות, כדי שלא ייחתכו/יידחסו במסכים צרים (320px ומטה), בלי צורך במספר breakpoints נפרדים.
- **`flex-wrap`** על פתקי הקטגוריות ועל שורות הכותרת - כך שבמובייל הם פשוט נופלים לעמודה אחת, ולא נגלשים הצידה.

מה שעדיין לא נכנס בסיבוב הזה (ונשאר להמשך): טסטים ספציפיים לגדלי מסך (viewport testing), ותמיכה מלאה ב-Safe Area על מכשירי iOS עם notch.
